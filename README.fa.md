# google-way-out

یک تونل SOCKS5 که ترافیک شما را از طریق Google Apps Script هدایت می‌کند و با استفاده از تکنیک domain fronting، اتصالات را از زیرساخت گوگل عبور می‌دهد. سرعت کاملاً بهینه نخواهد بود، اما نسبت به روش‌های قدیمی مشابه بهبود قابل توجهی دارد و امکان مرور آزاد در محیط‌هایی که دسترسی مستقیم مسدود است را فراهم می‌کند.

---

## نحوه کارکرد

سیستم از سه بخش تشکیل شده است:

**کلاینت** — فایل `client.py` روی دستگاه شما اجرا می‌شود و یک پروکسی SOCKS5 روی پورت 1080 باز می‌کند. هنگامی که مرورگر یا برنامه شما از طریق این پروکسی متصل می‌شود، کلاینت فریم‌های اتصال را دسته‌بندی کرده و به آدرس Google Apps Script شما ارسال می‌کند. اتصال از طریق TLS به یک آی‌پی ثابت گوگل برقرار می‌شود و SNI آن روی `www.google.com` تنظیم شده، به این ترتیب از دید خارجی درخواست مانند ترافیک عادی گوگل به نظر می‌رسد. یک حلقه پولینگ هوشمند با حداقل تأخیر اجباری، از مصرف تمام سهمیه روزانه URL Fetch گوگل (۲۰٬۰۰۰ درخواست در روز) جلوگیری می‌کند.

**Google Apps Script** — فایل `google-script.gs` به عنوان رله عمل می‌کند. درخواست دریافت‌شده از کلاینت را پردازش می‌کند، آدرس VPS هدف و محتوای پیام را استخراج کرده و با `UrlFetchApp` به VPS شما ارسال می‌کند. پاسخ VPS را عیناً به کلاینت برمی‌گرداند.

**سرور** — فایل `server.py` روی VPS شما اجرا می‌شود. فریم‌های تونل‌شده را از رله دریافت می‌کند، اتصال TCP واقعی به هاست‌های مورد درخواست را برقرار می‌کند و داده‌ها را از همان کانال به کلاینت برمی‌گرداند.

مسیر کلی داده:

</div>

```
اینترنت → server.py (VPS) → Google Apps Script → client.py → SOCKS5 (localhost:1080) → برنامه شما
```

## پیش‌نیازها

- یک VPS با آدرس آی‌پی عمومی
- یک حساب گوگل برای استقرار Google Apps Script
- نسخه ۳.۸ یا بالاتر از Python روی دستگاه کلاینت
- نصب کتابخانه `aiohttp` روی VPS

---

## راه‌اندازی

### ۱. استقرار Google Apps Script

۱. به آدرس [script.google.com](https://script.google.com) بروید و یک پروژه جدید بسازید.

۲. محتوای فایل `src/google-script.gs` را در ویرایشگر قرار دهید.

۳. از منو روی **Deploy > New deployment** کلیک کنید.

۴. نوع را روی **Web app** تنظیم کنید.

۵. گزینه **Execute as** را روی حساب خودتان و **Who has access** را روی **Anyone** قرار دهید.

۶. روی **Deploy** کلیک کنید و آدرس deployment را کپی کنید. شکلی شبیه به این خواهد داشت:

</div>

```
https://script.google.com/macros/s/YOUR_SCRIPT_ID/exec
```

<div dir="rtl">

### ۲. راه‌اندازی سرور روی VPS

فایل `src/server.py` را به VPS خود کپی کنید، سپس کتابخانه مورد نیاز را نصب کنید:

</div>

```bash
pip install aiohttp
```

<div dir="rtl">

سرور را اجرا کنید. به صورت پیش‌فرض روی پورت 8080 گوش می‌دهد:

</div>

```bash
python3 server.py
```

<div dir="rtl">

برای استفاده از پورت دیگر، شماره پورت را به عنوان آرگومان بدهید:

</div>

```bash
python3 server.py 9000
```

<div dir="rtl">

مطمئن شوید که پورت انتخابی در فایروال VPS شما باز است. سرور یک endpoint در اختیار می‌گذارد که آدرس آن `POST /tunnel` است.

به صورت اختیاری می‌توانید متغیر `AUTH_TOKEN` را در فایل `server.py` روی یک رشته مخفی تنظیم کنید تا از استفاده غیرمجاز از رله جلوگیری شود.

### ۳. پیکربندی و اجرای کلاینت

فایل `src/client.py` را باز کنید و دو متغیر زیر را در ابتدای فایل تغییر دهید:

</div>

```python
SERVER_URL = "https://script.google.com/macros/s/YOUR_SCRIPT_ID/exec"
VPS_URL    = "http://YOUR_VPS_IP:8080/tunnel"
```

<div dir="rtl">

اگر `AUTH_TOKEN` را در سرور تنظیم کرده‌اید، همان مقدار را در کلاینت نیز وارد کنید.

کلاینت به هیچ کتابخانه اضافی نیاز ندارد. برای اجرا:

</div>

```bash
python3 client.py
```

<div dir="rtl">

### ۴. پیکربندی مرورگر یا برنامه

مرورگر یا برنامه خود را روی پروکسی SOCKS5 در آدرس `127.0.0.1:1080` تنظیم کنید. در اکثر مرورگرها این گزینه در بخش تنظیمات شبکه یا پروکسی قرار دارد.

## مزایا نسبت به ابزارهای مشابه

- **پشتیبانی از اتصالات استریمینگ** — برخلاف ابزارهای ساده رله HTTP، این پیاده‌سازی اتصالات را در طول پولینگ زنده نگه می‌دارد، بنابراین چت‌بات‌ها و APIهای استریمینگ به درستی کار می‌کنند.
- **محافظت از سهمیه** — یک الگوریتم backoff تطبیقی به همراه حداقل تأخیر اجباری بین درخواست‌ها، مانع از مصرف سریع سهمیه ۲۰٬۰۰۰ درخواست روزانه URL Fetch گوگل می‌شود. میزان مصرف در فایل `gas_quota.json` ذخیره می‌شود.
- **نیازی به اعتماد به گواهی‌نامه نیست** — نیازی به نصب یا اعتماد به هیچ گواهی‌نامه سفارشی روی دستگاه شما وجود ندارد.
- **نیازی به دسترسی بالا نیست** — نه روی کلاینت و نه روی سرور، نیازی به دسترسی `sudo`، `root` یا Administrator نیست.

## عملکرد

تأخیر به صورت ذاتی بیشتر از یک اتصال مستقیم است، زیرا هر درخواست از زیرساخت script گوگل عبور می‌کند. با این حال، این پیاده‌سازی به طور قابل توجهی سریع‌تر از روش‌های قدیمی مشابه است. اتصالات HTTP keep-alive، الگوریتم پولینگ تطبیقی و پشتیبانی از استریم در مجموع سربار را به میزان زیادی کاهش می‌دهند. این ابزار برای مرور روزمره وب و استفاده از API به خوبی مناسب است.
